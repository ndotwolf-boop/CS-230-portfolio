# CS-230-portfolio

## Module Eight Portfolio Reflection

### 1. Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room was a client that wanted to expand their existing Android game, Draw It or Lose It, into a web-based application that could work across multiple platforms. The game needed to support multiple teams and players while making sure each game, team, and player had a unique ID. The client also wanted the application to be scalable, secure, and accessible from different devices and operating systems.

### 2. What did you do particularly well in developing this documentation?

I think one thing I did well was organizing the software requirements and comparing different operating platforms. I was able to look at the advantages and disadvantages of Windows, Linux, macOS, and mobile platforms to determine which would work best for the client. I also think I did a good job explaining how using object-oriented programming and design patterns could make the application easier to maintain and expand.

### 3. What about the process of working through a design document did you find helpful when developing the code?

Working through the design document helped me understand why planning is important before writing code. Breaking down the requirements and identifying the different classes and their responsibilities made it easier to understand how everything should work together. For example, using a Singleton pattern for the GameService class helped ensure that only one instance would manage the game's information. Having a clear design made the development process more organized.

### 4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one part of my documentation, I would probably expand on the security and distributed systems sections. I would include more details about how the application would handle network interruptions, protect user information, and manage communication between the server and different devices. I think adding more specific examples would make the document easier for another developer to follow.

### 5. How did you interpret the user's needs and implement them into your software design? Why is it important to consider the user's needs?

I approached the client's requirements by focusing on making the application accessible, reliable, and easy to expand. Since The Gaming Room wanted their game available on multiple platforms, I recommended a centralized server approach that would allow users to access the application through different devices. I also considered scalability and security because the application would need to support multiple users. Understanding the client's needs is important because even well-written software won't be successful if it doesn't accomplish what the client actually wants.

### 6. How did you approach designing software? What techniques or strategies would you use in the future?

My approach was to start by understanding the requirements, identifying the major components, and comparing the available platforms before making a recommendation. I used concepts like object-oriented programming, design patterns, and system architecture to help organize the application. In the future, I would continue using this approach, but I would also spend more time creating diagrams, considering potential problems, and planning how the application could grow. This course helped me understand that software development involves more than just writing code. Having a good design can make a big difference in how reliable and maintainable an application becomes.
